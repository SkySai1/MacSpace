# Модуль локальных снимков Time Machine

## Эксплуатация

Откройте вкладку **Time Machine** в верхнем переключателе или боковой панели. При первом открытии MacSpace читает даты локальных снимков на всех подключённых дисках. `⌘R` или кнопка обновления повторяет чтение. Анализ папки и Корзины сохраняется при переключении.

Одна строка представляет все локальные снимки одной даты на подключённых дисках: именно так работает системная команда удаления по дате. Это не список резервных копий диска назначения. Системные снимки обновлений macOS и снимки сторонних приложений здесь не управляются.

Выберите строки через Command/Shift и нажмите **Удалить выбранные…**. **Очистить все…** фиксирует все даты текущего списка. В подтверждении указаны даты и область действия — все подключённые диски. Удаление безвозвратно: восстановление из удалённых локальных снимков станет недоступно. Новые даты, появившиеся после подтверждения, в операцию не включаются. Для одного и того же времени на разных томах снимки удаляются вместе.

После подтверждения macOS запрашивает права администратора. Пароль обрабатывает системный диалог, приложение его не запрашивает и не сохраняет. При отказе macOS приложение показывает ошибку и кнопку повторного чтения. Если система требует полный доступ к диску, откройте **Настройки доступа…**, разрешите его для MacSpace и перезапустите приложение. После отмены запроса, тайм-аута или частичного отказа сначала обновите список; автоматического повторного удаления нет.

`tmutil` не сообщает размеры отдельных снимков. Сумма размеров файлов снимка не равна потенциально освобождаемому месту из-за совместных блоков APFS. Поэтому приложение показывает даты, а не вычисленный размер или обещанный объём освобождения. Восстановление файлов и просмотр содержимого снимков не реализованы. macOS также может автоматически удалять устаревшие локальные снимки.

## Техническое устройство

`Sources/MacSpaceCore/TimeMachineService.swift` содержит:

| Компонент | Назначение |
| --- | --- |
| `LocalTimeMachineSnapshot` | Неизменяемые ID `YYYY-MM-DD-HHMMSS` и дата; ASCII-формат и календарная корректность проверяются конструктором |
| `TimeMachineManaging` | Внедряемый асинхронный интерфейс `list/delete` |
| `TimeMachineService` | Actor, чтение и строгий разбор списка, повторная проверка дат перед удалением, разбор результатов каждой даты |
| `SystemTimeMachineRunner` | Фоновый `Process`, объединённый поток stdout/stderr, отмена и тайм-аут |
| `TimeMachineDeleteResult` | Подтверждённо обработанные даты и отдельные ошибки |

Чтение вызывает `/usr/bin/tmutil listlocalsnapshotdates` без прав администратора с `LC_ALL=C`. Заголовок и каждая дата проверяются; неизвестный вывод вызывает ошибку вместо ложного пустого списка. Дубликаты дат объединяются, порядок — от новых к старым.

Удаление сначала перечитывает только список дат. Уже исчезнувшие даты исключаются без запуска команды администратора. Для оставшихся формируется фиксированный набор `/usr/bin/tmutil deletelocalsnapshots '<date>'`. Не используются пути, wildcard, удаление всего тома или `thinlocalsnapshots`. Строка shell экранируется для AppleScript и передаётся аргументом `/usr/bin/osascript -e`; `do shell script … with administrator privileges` выполняет пакет с одним системным запросом авторизации. Коды возврата каждой даты отделяются маркерами и разбираются независимо. Неполученный код не считается успехом.

Работа с процессами, чтение pipe и ожидание завершения выполняются в `Task.detached`, вне главного потока. Тайм-аут чтения — 60 секунд, авторизации/пакета — 300 секунд. Прерывание управляющего процесса не гарантирует отмену уже запущенной системной операции; при неопределённом результате требуется обновление.

`Sources/MacSpace/TimeMachineModel.swift` хранит список, множественное выделение, время чтения, состояние загрузки/удаления и зафиксированный набор подтверждения. UUID поколения исключает опоздавшие результаты. После подтверждённых успехов удаляются только соответствующие строки из ОЗУ; анализ файлов не перезапускается, сохранённые размеры файлов не меняются. При ошибке чтения прежний список остаётся виден, команды удаления блокируются до успешного обновления.

`TimeMachineView.swift` отображает таблицу, выбор, ошибки доступа и подтверждение. `AppModel` передаёт изменения вложенной модели интерфейсу, сохраняет две файловые рабочие области и блокирует переключение вкладок на время удаления. Чтение начинается только при открытии вкладки. Внешние/недоступные тома обслуживает `tmutil`; отказ системной утилиты отображается пользователю.

## Проверка и ограничения

`TimeMachineServiceTests` проверяет разбор, неверные/инъекционные даты, точный набор команд, исчезнувшие даты, частичный отказ, отмену авторизации, неподтверждённый ответ, экранирование AppleScript, коды shell, тайм-аут и отмену процесса. Команды удаления и авторизации подменены. Безопасная проверка shell запускает только `false/printf`; тест AppleScript возвращает строку без системного диалога.

`TimeMachineModelTests` проверяет подтверждение/отмену, независимость одобренного набора от последующего выделения, частичный отказ, отказ чтения, устаревший результат, сохранение анализа/Корзины и блокировку навигации. `RenderingTests` отрисовывает таблицу в двух оформлениях, ошибку доступа и пустое состояние через тестовую службу.

Запуск: `./scripts/swift-local.sh test`. Настоящие снимки, резервные копии и настройки Time Machine в автотестах не изменяются. Реальное удаление и системная авторизация удаления не проверялись. Безвредный вызов AppleScript `do shell script "/usr/bin/true"` проверен вне sandbox среды разработки; в sandbox недоступна загрузка Standard Additions. Приложение собирается без App Sandbox.

Семантика команд проверена по локальному `man tmutil`. Поведение локальных снимков описано в [документации Apple](https://support.apple.com/en-us/102154).
