# Модуль обновления снимка после переноса

## Эксплуатация

После успешного переноса файлов и папок в Корзину приложение исключает их из таблицы, шкал и карты. Размеры, доли и число объектов уменьшаются у всех родителей. Полный анализ не запускается. Если была открыта удалённая папка или её потомок, открывается ближайшая оставшаяся папка; выбор удалённых объектов сбрасывается.

Остальные данные остаются такими, какими были при исходном сканировании. Для учёта изменений из Finder, восстановления из Корзины или новых файлов нажмите `⌘R`.

## Техническое описание

`Sources/MacSpaceCore/SnapshotRemoval.swift` реализует чистое преобразование `ScanSnapshot.removingSubtrees(ids:) -> ScanSnapshot`; одиночный removingSubtree вызывает его с одним ID. Выбор нормализуется: выбранный родитель уже включает потомков. Один пакет удаляется одним преобразованием, с общей обработкой жёстких ссылок и одним копированием словаря. Вызов не переносит и не читает файлы. Приложение передаёт только успешные ID переноса или очистки; при частичном отказе остальные узлы сохраняются.

1. Собрать ID удаляемого узла и его потомков итеративным обходом сохранённых `childIDs`.
2. Убрать эти узлы и ссылку на корень поддерева из списка детей родителя.
3. Вычесть сохранённые логический и выделенный размеры, число узлов и `scanIssueCount` из цепочки предков. Остальные размеры заново не суммируются.
4. Если исходный путь учёта жёсткой ссылки удалён, найти оставшиеся ссылки на тот же `(device, inode)` в снимке и перенести выделенные блоки на один из них. Родителям нового пути добавить эти блоки; логические размеры других имён не меняются. Последовательные переносы сохраняют этот инвариант.
5. Удалить описания ошибок внутри удалённого пути по компонентам пути. Полный счётчик уменьшается на `scanIssueCount`, даже если часть описаний не попала в лимит 200. При наличии места известные описания ошибок восстанавливаются из оставшихся узлов.
6. У повторного пути каталога, чей первоначальный узел удалён, сбросить ссылку на отсутствующий узел и отметить необходимость ручного обновления содержимого. Новый обход не запускается автоматически.

Время и длительность сканирования, общая ёмкость и свободное место тома сохраняются. Перенос в Корзину обычно не освобождает блоки на томе, поэтому размер удалённой папки не прибавляется к свободному месту.

Стоимость преобразования зависит от размера удаляемого поддерева, высоты дерева и числа оставшихся узлов, проверяемых для учёта общих данных. Все операции выполняются в памяти; преобразование вызывается в фоновом `Task.detached`, чтобы не блокировать интерфейс. Удаление отсутствующего ID или корня возвращает исходный снимок.

## Ограничения и проверка

Вычитаются значения исходного снимка. Изменения файлов после сканирования не перечитываются, время снимка не обновляется. Непрочитанные данные по-прежнему не входят в суммы. Для повторного пути каталога без сохранённых детей приложение не может восстановить его содержимое из удалённого пути автоматически; доступно ручное обновление.

`SnapshotRemovalTests` проверяет вычитание размеров и счётчиков, сохранение остальных узлов и времени, повторное применение, защиту корня, жёсткие ссылки в разных порядках, удаление ошибок при лимите 200 и отсутствие ссылок на удалённый каталог. `TrashUpdateTests` проверяет весь путь через модель приложения с переносом только тестовых данных во временный каталог, включая ошибку переноса и навигацию. Запуск: `./scripts/swift-local.sh test`.
